# Contributing

Thanks for stopping by. Bug reports, ideas, typo fixes and pull requests are all welcome, in that order of how quickly they get a reply.

These are [Lean Mean Clean Apps](https://leanmeancleanapps.github.io/) projects, built and looked after in spare time by a small team, with strong coffee and a healthy disregard for pomp and ceremony. Small as in one person, for now, so replies are best effort, and the fastest way to get something changed is to make it easy to say yes to. If you'd like to make it two, pull requests are how that starts.

## Before you start

- Be kind. The [code of conduct](CODE_OF_CONDUCT.md) says how.
- Search the issues first. Someone may have beaten you to it.
- For anything bigger than a small fix, open an issue before you write the code, so we can agree on the approach before you spend an evening on it.
- Found a security problem? Don't open an issue. Follow the [security policy](SECURITY.md) instead.

## Which repository

| You want to change | Go to |
| --- | --- |
| A template | That template's own repository. Each one has its own contributing guide, because they have real build rules and a 95% coverage gate that doesn't negotiate. |
| A logo, colour, token or social template | [brand](https://github.com/LeanMeanCleanApps/brand). Everything there is generated, so change the scripts and commit what the build makes. |
| The website | [leanmeancleanapps.github.io](https://github.com/LeanMeanCleanApps/leanmeancleanapps.github.io). One page, Astro, no framework drama. |
| The organisation profile or these shared files | [.github](https://github.com/LeanMeanCleanApps/.github). |

## Making a change

1. Fork the repository and branch from `main`. Name the branch `feature/`, `fix/` or `chore/` followed by a few words, like `fix/favicon-size`.
1. Keep it focused. One change per pull request makes it quick to review, and quick to review means quick to merge.
1. Run whatever the repository's README tells you to run before you push. Each one is small and says so.
1. Open the pull request against `main`, fill in the template, and link the issue if there is one.

Every pull request is reviewed by the maintainer before it goes in. That's not a lack of trust, it's just how the lights stay on. If a review takes a while, a polite nudge is fine.
